# N5「試す」の計画（案）— 2026-10-03 JST

**ねらい:** アプリの見込みが、実際の記録とどれだけ合うかを確かめます。見込みとは、ボーナスの取り分・値動きの損・費用・保険のことです。
合わないところは計算を直します。「仮」の数字は、試した結果から決め直す案を出します。
動かすのは計算と練習だけです。お金を動かすコード（署名・送金）は書きません（絶対ルール1）。

目安は **6〜8日**（SPEC 13.4 の 5〜7日に、Merkl の答え合わせの分を1日足しました）。PR は4つに分けます（「4. 日数と PR の分け方」）。

用語（この計画で使うことば）
- **見込み**: アプリが「この場所にいくら置くと、1日にいくら残る」と出す数字です。内訳は、ボーナスの取り分・手数料・値動きの損・置き直しの費用・保険の費用・ボーナスのコインの値下がりです。
- **実際の記録**: チェーンの記録（ブロックに残った値段・流動性・配られた額）と、Merkl が公開している「誰にいくら配ったか」です。
- **過去の記録で試す（さかのぼり）**: もう起きたことに見込みの式を当てはめて、外れ方を見ます。すぐ結果が出ます。
- **これから試す（影の記録）**: 今の見込みを毎時間メモしておき、1日後・7日後に実際と比べます。結果が出るまで日数がかかります。

## 1. 何を確かめるか

見込みの部品ごとに、「何と比べるか」と「どれだけ合えばよいか（仮の目安）」を決めます。
目安は、2週間の評価で使った「見込みとの差が見込みの30%以内、または資金の0.1%以内」に合わせます。

| 部品 | 見込み（アプリの数字） | 比べる実際の記録 | 合格の目安（仮） |
|---|---|---|---|
| ① ボーナスの取り分 | 自分の流動性 ÷ 幅の中の流動性 × 配る額 | Merkl が実際に配った額（受け取った人ごと）、up. ではチェーンの配る速さ（rewardRate）と幅の中の流動性 | 1日ごとの差が30%以内の日が7割以上 |
| ② 幅の中にいた割合・置き直しの回数 | 値動きの大きさ（σ）から出した見込み | 15分ごとの値段の記録で、同じ幅を置いたら何回外に出たか | 回数の差が30%以内 |
| ③ 値動きの損（ガンマ） | 見込みの式 | 値段の記録で、同じ幅の中身を動かして計算した損 | 1日ごとの差が30%以内、または資金の0.1%以内 |
| ④ 費用 | ガス代・両替のずれ・保険の手数料 | チェーンの記録のガス代、プールの流動性から計算したずれ、Lighter の手数料表 | 差が30%以内 |
| ⑤ 保険 | 資金調達料・強制決済までの余裕 | Lighter の資金調達率の記録、過去の大きな値動き（市場が開く時の飛び） | 過去の値動きで、+50% に耐える預け金が足りていたか |
| ⑥ 早く出る決まり | 4段階の合図 | 過去の記録で同じ決まりを当てはめたとき、いつ出たか、出たあとに値段がどうなったか | 出たことで避けられた損と、出なければ得られた分を並べる |

試験の例としてかならず入れるもの（あなたのパソコンで確かめた記録）:
- 10/1 21:45 の UP の自動の早出（−22.8%。docs/cases/early-exit-up-2026-10-01.md）
- 評価中の大きな値動き（SPY −50.3%、SNDK −40.4%。どちらも「プールのお金が1時間で−50%」の線の近く）

## 2. 何で確かめるか

### 2-1. 過去の記録で試す（N5 で結果まで出す）

| 記録 | どこにあるか | 何に使うか |
|---|---|---|
| 今の版（18000）が9月末から15分ごとに集めた up. のプールの記録と、評価中の建玉の記録 | あなたのパソコン（今の版のデータ） | ②③⑥、UP の早出の例 |
| 新しい版（18001）が10/2から集めている Merkl の一覧（15分ごと）と、幅に配るプールの値段・流動性（1時間ごと） | あなたのパソコン（新しい版のデータ） | ①②③ |
| チェーンの記録（Robinhood Chain・Base） | 公開の読み取り口 | up. の配る速さ・流動性の過去、ガス代 |
| Merkl が公開している、キャンペーンごとの配った額（受け取った人ごと） | Merkl の公開 API | ①の答え合わせ（2-3） |
| DefiLlama の利回りと預かり額の毎日の記録（数か月分） | DefiLlama の公開 API | 「最初から入っていたら」（SPEC 13.2 の「試す」）、損の線のふだんの揺れ |
| Lighter の資金調達率の記録 | Lighter の公開 API | ⑤ |

- 今の版のデータには、**読むだけ**で触りません。新しい版が、今の版のデータの**写し**を読みます（判断①）。
- 写しを作る1行は、今の版を止めずに読み取り専用で写します。前に m4-wrong を確かめたときと同じやり方です。

### 2-2. これから試す（影の記録。N5 で始めて、N6 の練習と一緒に続ける）
- 「探す」の一覧に出る行（狙い利回り以上と、上位の行）について、毎時間の見込みをメモします。メモするのは、金額ごとの取り分・幅・費用・保険です。
- 建玉は作りません（ボタンなし。SPEC 13.2 の「評価のボタンなしで自動で記録し、あとから期間を切り出して判定する」）。
- 1日後・7日後に、その時間に実際に起きたこと（チェーンの記録・Merkl の配った額）と比べます。
- N5 の終わりには、まだ数日分しかたまりません。そのため、決め直しには主に 2-1 の結果を使います。影の記録は N6 の間の確かめに使います。

### 2-3. Merkl の「実際に配った額」との答え合わせ（「全員」と「幅の中だけ」の数え方を決め直す件）
- 今の決め方（13.1 の追加の決定 8 で A）: 幅に配るプールで、コイン0・コイン1の重みで配る分は、**プールに預けられたお金の全部**を分母にしています（控えめ）。
- Merkl の資料には「ふつうは、幅の中にある預け方だけに配る」と書いてあります（例外は、利回りを固定するキャンペーン）。キャンペーンの設定にも「幅の外にも配るか」の印があります。つまり「幅の中だけ」のほうが近い見込みです。数字で確かめてから決め直します。
- Merkl が無料で見せている記録（2026-10-03 に作業場所で確かめた）:
  - キャンペーンごとに、**預け方1つごと**（受け取った人と、その人の預け方の番号）の「これまでに配った合計」。
  - キャンペーンごとの「これまでに配った合計」と、最初に決めた「配る予定の総額」。
  - 配る額の更新は、Base ではいま約2時間ごとです。
- **期間ごとの差（この2時間にいくら配ったか）は、Merkl の API キーがないと読めません。** そのため、答え合わせは次のやり方にします（判断②）。
  1. Base と Robinhood Chain で今動いている、幅に配るキャンペーンを選びます。
  2. 約2時間ごとに「預け方ごとの合計」を保存し、前の回との差を取ります。これで、その2時間に各預け方がもらった額がわかります。
  3. その預け方の幅と量を、チェーンの記録で読みます（預け方の番号から読めます）。
  4. 同じ2時間の値段と流動性（新しい版が1時間ごとに保存）で、「全員を分母」「幅の中だけを分母」の2つの式で取り分を計算します。
  5. 実際の額にどちらが近いかを、重みの種類（手数料・コイン0・コイン1）ごとに比べます。
- 過去の分は「配った合計 ÷ 配る予定の総額」と、キャンペーンの経過日数を比べる（配るペースが見込みどおりか）だけに使います。
- 結果で、決定 8 を「そのまま」か「幅の中だけに変える」かの案を出し、あなたに決めてもらいます。
- Merkl の資料に書かれていない仕組みは、推測で埋めません。合わなかったら、合わなかったことを報告します（絶対ルール4）。

### 2-4. 比べる相手（SPEC 13.2「何もしない場合、レンディングに置いた場合と比べる」）
- 何もしない（ドルのコインのまま持つ）
- ドルのコインの貸し出し（Base の大きい貸し出し先の利回り。DefiLlama の記録。出典と確認日をつけます）
- 幅を広く置きっぱなし（置き直さない）

## 5. 判断が必要な点

**判断① 今の版（18000）の記録の使い方**
- **A（おすすめ）**: 1行で今の版のデータの写しを作り、新しい版が自分で読んで試す。今の版は止めず、触りません。写しは新しい版のフォルダーの中に置きます。
  理由: アプリが自分で試せるので、何度でもやり直せます（SPEC の「調べるはチャットに頼まず、アプリが自分で集める」）。
- B: 必要な分だけを小さいファイルに書き出し、あなたがチャットに添付する。作業場所で試します。
  理由: パソコンの手順は少ないです。ただし、試すたびに添付が要ります。

**判断② Merkl の答え合わせのやり方**
- **A（おすすめ）**: これからの記録で答え合わせする。Base と Robinhood Chain で今動いている、幅に配るキャンペーン全部を、約2時間ごとに保存します。キーは要りません。
  理由: 無料で読める記録だけでできます。N5 の終わりには数日分（1キャンペーンで数十回分）がたまり、重みの種類ごとに比べられます。
- B: Merkl の API キーを申し込んで、過去30日の期間ごとの記録も使う。キーはあなたが .env に書きます（チャットには書きません）。
  理由: 過去の分まで比べられます。ただし、申し込みの手間と待ち時間があり、キーで読める期間にも区切りがあります。

**判断③ 影の記録の範囲**
- **A（おすすめ）**: 一覧に出る行（狙い利回り以上と、上位30行）を毎時間。保存は1日数MBの見込みです。
- B: 狙い利回り以上の行だけ。
  理由: 保存は少ないです。ただし、狙いより少し下の行の答え合わせができません。
