## 1. 全体の形

データの読み方と計算を分けて、計算から先はチェーンを知らない作りにします。ソラナ系を足すときは、「読み方」を1つ足すだけです（下の図）。

**図: 全体の形（読み方だけが系統ごとに違い、計算から先は全部共通）**

```
[読み方（ETH系）]            [外のデータ]                    [読み方（ソラナ系）※将来]
 型: 幅・全体・投票・あとから   Merkl・DefiLlama                同じ形の数字を渡すだけで、
 登録: 会場の住所と出典         送金サービス・コインの値段       計算は共通
        │                          │                               ┆
        ▼                          ▼                               ▼
[決まった形の数字（系統 ＞ チェーン ＞ 会場 ＞ プール）]
 値段・対象の量・1日のボーナス・配り方・残り日数・預かり額・運営の鍵
        │                          │                               │
        ▼                          ▼                               ▼
[見つける]                     [計算する]                      [守る]
 立ち上げの合図・候補の収集      本当に残る利回り（金額ごと）     置き場所・危なさの点数
 ふるい分け（残り日数など）      取り返す日数・入れてよい上限     推奨金額・全体の損の線
        │                          │                               │
        ▼                          ▼                               ▼
[決まりの表（入る・4段階で出る・移る・止め方）]
 練習でも、過去のデータで試すときも、同じ表を使う
        │                          │                               ┆
        ▼                          ▼                               ▼
[練習（今）]                   [試す]                          [本番（Phase 3）※作らない]
 建玉を持てば自動で記録          過去のデータ・いろいろな場面      「Phase 3aを開始」まで作らない
        │                          │
        ▼                          ▼
[記録と画面]
 台帳（税金用に書き出す）・機会／渡る／守る／試すのページ・知らせ
```

- 登録は「系統 ＞ チェーン ＞ 会場 ＞ プール」の4段です。会場には「仕組みの型」を書き、型ごとの読み方を使います。
- 仕組みの型は、お願いの5つに1つ足して6つにします: 幅に配る型、全体に配る型、投票で決める型（週ごとと、Aero や STONX のようにいつでも変わるものの2種類）、あとから配る型（Merkl など）、ポイント型、それに取引量で配る型（1inch Aqua。預かり額からは利回りを計算できないため分ける）。1つの会場が2つの型を持つこともあります（例: Aerodrome は投票で決める型で、プールには幅に配る型と全体に配る型の両方がある）。
- 本番（Phase 3）は形だけ用意し、作りません。練習と試すは、同じ「決まりの表」で動きます。

### 2.3 Merkl の自動収集

Merkl は 69 のチェーンで、いま 928 のキャンペーンが動いています。1日に約58件増えます。読むのにキーは要りません。

10〜30分ごとに、対象のチェーンの「動いている」と「予定」の両方を読みます。予定のキャンペーンは、真ん中の値で始まる約1時間前にしか出てきません。3件に1件は、始まったあとに作られます。だから1日1回では間に合いません。

表示の利回りは使いません。配り方ごとに、自分のお金を入れたあとの利回りを計算し直します（3章）。

- 山分け型: 入れるほど下がる。
- 上限つき型: 上限に届いている間は、しばらく薄まらない。
- 固定型: 入れた額によらず一定。予算が尽きると早く終わる。

最初に外すもの、印を付けるもの（数字は仮）:

- 報酬がポイントや、まだ売れないコイン: 928件のうち177件。別の欄に量だけ出す。
- 特定の利用者だけのもの（名簿つき、「Robinhood のアプリの利用者だけ」など）: 参加できないとして外す。
- 残りの日数で移る費用を取り返せないもの: 外す。
- 預かり額が小さすぎるもの（$5万未満）: 外す。ただし 2.4 の新しいプールは別に扱う。
- 利回りを作った人が自分で出している型: 印を付けて計算し直す。実際に計算すると、表示の 0.5〜2倍の幅でずれていた。
- 報酬を別のチェーンで受け取る型: 印を付ける（受け取りの手間とガス代）。
- 利回りが高すぎるもの（年1,000%以上）: 警告を出す。

続きがあるかも読みます。同じキャンペーンの延長が予定に入っているか、行き先のプールが変わったかを見ます。今日の例では、Robinhood Chain の SPY の組み合わせ14件が 10/1 22:00 から 10/15 まで延長されました。そのうち5件は、報酬の行き先が別の新しいプール（預かり額 $0）に移りました。古いプールに置いたままの人は、そこから報酬が0になります。

報酬が届くまでの時間も数えます。報酬はチェーンに2〜8時間ごとに書き込まれ、受け取れるまで最大で約12時間かかります。キャンペーンが終わると、受け取っていない報酬を作った人が引き上げられることがあります。そこで、練習でも「受け取り」を記録し、終わる前に受け取る決まりにします。

### 2.4 早く入る得は「新しいプール」にだけある

7月からあとに終わったプール型のキャンペーン100件を調べました。

- もともと預かり額があるプール（80件）: 利回りは1日目 年27%、7日目 年30% で、ほぼ変わらない。
- 始まったときの預かり額が $2万未満の新しいプール（20件）: 1日目 年256%、3日目 年212%、7日目 年112%。1週間で半分以下になる。

そこで、「新しいプールで始まる予定のキャンペーン」を一番強い合図にします。新しいプールは自分のお金でも大きく薄まるので、入れる量は3章の「金額ごとの利回り」で決めます。

### 2.5 登録は2段階

- 段階A（住所の登録なし）: Merkl と DefiLlama の数字だけで「機会」に出します。見るだけで、練習では入りません。
- 段階B（自分で読む）: プールや会場の住所を、公式の資料かエクスプローラーで確かめて設定ファイルに書きます（出典と確認日。絶対ルールの3）。練習で入るのは段階Bの場所だけです。

読み方の「型」（Uniswap 型、Aerodrome 型、Merkl 型）を作るので、新しいチェーンでも住所の登録だけで読めます。アプリが住所の候補と出典を出し、実装役が確かめて登録します。

### 2.6 新しいチェーンに入るまでの段階

合図 → 浅く調べる → 少ない金額で入る → 様子を見て増やす、の順に進みます。

1. 浅く調べる: アプリが自動で集めます。チェーンの年齢（最初のブロックの時刻）、会場の年齢・監査・運営の鍵・事件・バグ報奨金、送金サービスの対応、出口の経路とかかる時間、ガス代、ボーナスのコインの売り場。これが5章の危なさの点数になります。
2. 少ない金額で入れて出す試し: 本物のお金なので、Phase 3 まではアプリは動かしません。アプリは手順の表を出し、オーナーが行った結果（かかった費用と時間）を記録する欄を用意します。練習では、送金サービスの見積もりで費用と時間を数えます。
3. 様子を見て増やす: 最初は上限の一部（仮: 4分の1）で入り、仮に3日続けて問題がなければ、5章の上限まで増やします。

## 3. 計算する（本当に残る利回り）

すべての機会を「本当に残る利回り」だけで比べます。自分のお金を入れたあとの値で、全部の費用を引いたものです。入る・出る・移るの決まりも、この数字だけを使います。

```latex
\text{残る利回り(1日)} = \text{ボーナスの取り分} \times \text{すぐ売った値段} - \text{売るときの値崩れ} + \text{手数料} - \text{値動きの目減り} - \text{置き直し} - \text{保険} - \frac{\text{移る費用}}{\text{いる日数}}
```

| 項目 | 数え方 | 今のコード |
| --- | --- | --- |
| ボーナスの取り分 | 1日のボーナス × 自分の量 ÷（今の対象の量＋自分の量）。自分で薄める分がここで入る | ある（up. の形だけ） |
| 配り方の違い | 幅に配る型は「幅の中にいる時間の割合」を掛ける。全体に配る型はそのまま。Merkl はキャンペーンごとの重み（手数料・2つのコイン）と「幅の外は0」を読む | 幅に配る型だけ |
| 人が集まって薄まる分 | 預かり額がこれから増える見込み。最初は控えめな仮置き（例: 残り期間の平均で今の1.5倍）、過去のデータで決め直す | ない |
| ボーナスのコインの値段 | 受け取ってすぐ売った値段。売る量での値崩れを、売り場の深さから引く | 「すぐ売る前提」が参考値としてある |
| 手数料 | LP が手数料を受け取る型だけ。出来高が預かり額の10倍を超えたら0 | ある |
| 値動きの目減り・置き直し | 今の評価で確かめている式をそのまま使う | ある（答え合わせ中） |
| 保険（Lighter） | 資金調達料＋取引手数料。担保のお金も「置いている場所」に数える | ある |
| 移る費用 | 送金＋交換＋ガス代（入るときと出るときの両方）。いる予定の日数で割る | ない |
| ポイント | 値段がないので「0」として数え、別の欄に量だけ出す（11章） | ない |

この計算から、機会ごとに次の4つを出します。

1. 金額ごとの利回り（$100、$1,000、$10,000、$100,000）。金額が大きいほど自分で薄め、売るときに値崩れするので、利回りは下がります。
2. 費用を取り返す日数 = 移る費用 ÷ 1日に残る額。キャンペーンの残り日数より長ければ、そこには移りません。
3. 入れてよい上限。自分がそのプールの 5%（仮。設定で変えられる）を超えない金額と、5章の危なさの上限の、小さいほう。
4. 「控えめ」と「ふつう」の2つの見込み。入るかどうかは「控えめ」で決めます。

比べる線は、レンディングの利回りに上乗せしたものです。土台は「年7%」と「日本から使えるレンディングの利回り」の高いほうにする案です。日本から使えるものは、今は年3.7〜4.5%（Base の Aave や Morpho の大きな USDC の貸し出し）で、アプリが自動で読みます。Robinhood Earn の7%は日本から使えないので、今は7%が土台になります。入る線を出る線より高くして、入ってすぐ出るのを繰り返さないようにします（数字は11章）。

計算の部分は、チェーンや会場を知らないように作ります。「読み方」が渡すのは、決まった形の数字（値段、対象の量、1日のボーナス、配り方の種類、残り日数など）だけです。ソラナ系を足すときは、読み方を足すだけで、この計算をそのまま使えます。

## 4. 早く出る・移る

出る決まりは、お願いの4段階をそのまま「決まりの表」にします。1行が1つの決まりで、数字と「止め方」（5章）はすべて設定で変えられます。練習でも、過去のデータで試すときも、同じ表を使います。

| 段階 | 決まり（数字は仮） | 読むもの | 今のコード |
| --- | --- | --- | --- |
| 1 すぐ逃げる | 預かり額が1時間で30%以上減った | プールが持っているコインの量 × 今の値段 | ある（50%で動く。線を設定にする） |
| 1 すぐ逃げる | 運営がプログラムや権限を変えた（持ち主・入れ替え・一時停止） | 会場のプログラムの持ち主と中身。時間を置く仕組みがあれば「予約された変更」も読む | ある（up. と Alandale） |
| 1 すぐ逃げる | ドル同士のコインが2%以上ずれた（2回続けて） | 外の値段と、プールの値段 | USDG の $0.98 だけ。持っているドルのコイン全部に広げる |
| 1 すぐ逃げる | 出口の送金サービスが止まった | 送金サービスの「使える経路」の一覧 | ない |
| 2 利益が消えた | 本当に残る利回りが「出る線」を3回続けて（45分）下回った | 3章の計算 | ない（今は信号機で判定） |
| 2 利益が消えた | ボーナスのコインが24時間で15%以上下がった | コインの値段 | ある（20%で動く） |
| 3 予定どおり | キャンペーンの終わりが近く、残りで移る費用を取り返せない | 終わる日時と、移る費用 | ない |
| 3 予定どおり | コインの大量解放が近い | 解放の予定表（取れない会場は「不明」と表示） | ない |
| 3 予定どおり | 投票で来週のボーナスが減ると分かった | 投票型の会場の票の数（切り替えの前に読む） | 半分ある（ボーナスが減ったときの記録だけ） |
| 4 もっと良い場所へ | 利回りの差 × 残り日数 ＞ 移る費用の2倍 | 3章の計算を、今いる場所と移り先の両方で | ない |

あわせて入れる決まり:

- ボーナスのコインはため込まず、毎日1回（設定で「受け取るたび」も選べる）ドルに替えます。練習では、その時の値段と値崩れで売ったことにして記録します。
- 入る前に、ボーナスのコインの売り場を確かめます。「1日に受け取る量を、値崩れ2%以内で売れるか」を見て、売れなければ入りません。
- 急がない出口（段階2〜4）は、ガス代がふだんの3倍を超えている間は待ちます（待つのは最長24時間。数字は仮）。段階1は待ちません。
- レンジの外に出たときの置き直しと、全体の損の線は、今の仕組みを残します（損の線は5章の新しい形に移します）。

練習を甘くしないための決まり:

- 練習では、出る判断をした「次の回」の値段で出たことにします。見つけてから出るまでの遅れを入れるためです。
- 段階1で出るときは、みんなが一度に逃げるので、ガス代と値崩れをふだんより重く数えます（仮: ガス代5倍、値崩れ3倍）。
- 本物のお金では、ハッキングのときに逃げられないこともあります（10章）。練習の結果は、本物より良く見えやすいものとして扱います。

見張る間隔は、持っている場所が15分ごと（米国市場の開場前後は5分ごと。今と同じ）、候補は1時間ごと、新しい合図は数時間ごとです。本物のお金で自動で逃げるようにするのは Phase 3 で、そのときは1分ごとにします（付録A）。

## 5. 守る

守りは「どこにいくら置いているか」を正しく数えることから始め、危なさの点数で金額の上限を決め、全体の損の線で止めます。数字はすべて設定で変えられ、上限の数字はオーナーが決めます（実装役は変えません）。

### 5.1 置き場所の帳簿

プールの建玉、保険（Lighter）の担保、送金の途中のお金、チェーンごとの財布の残り、まだ売っていないボーナスのコインを、すべて「置き場所」として数えます。ホームに「どこにいくら」の一覧と合計を出し、上限もこの合計で数えます。

### 5.2 資金の大きさで切り替える

- 小資金（仮: $2,000 未満）: 1か所に全額でよい。危なさ「とても高い」にも入れられるが警告を出す。移る費用が資金の1%（仮）を超えるチェーンは、候補から自動で外す。
- 大きい資金: 下の上限を守る。切り替えの金額は設定で変えられる。
- どちらでも「費用を取り返す日数」を毎回出し、キャンペーンの残り日数より長ければ移りません。

### 5.3 危なさの点数と推奨金額

チェーンと会場の組み合わせごとに、8つの項目を0〜3点で数えて足します（点が多いほど危ない）。区切りは仮で、過去の事件に当てはめて決め直します。

| 項目 | 0点 | 1点 | 2点 | 3点 |
| --- | --- | --- | --- | --- |
| チェーンが動いている期間 | 2年以上 | 6か月〜2年 | 3〜6か月 | 3か月未満 |
| 会場が動いている期間 | 1年以上 | 90日〜1年 | 30〜90日 | 30日未満 |
| 監査 | 2件以上で問題は直っている | 1件で直っている | 直っていない問題がある | なし |
| 運営の鍵 | 複数人の承認＋時間を置く仕組み | 複数人の承認 | 1つの鍵だが権限が小さい | 1つの鍵で何でもできる |
| 預かり額 | $50M 以上 | $5M〜$50M | $0.5M〜$5M | $0.5M 未満、7日で−30%以上 |
| 過去の事件 | なし | 1年以上前にあり、補償した | 1年以内にあり | 未解決 |
| バグ報奨金 | $100k 以上 | ある | 小さい | なし |
| ボーナスのコインの売り場 | 深い | ふつう | 浅い | 1日の受け取り分も売れない |

| 危なさ | 点の合計（仮） | 大きい資金のときの上限（仮、全体に対して） |
| --- | --- | --- |
| 低い | 0〜5 | 25% |
| 中くらい | 6〜10 | 15% |
| 高い | 11〜15 | 5〜10%、「高い」を合わせて全体の20%まで |
| とても高い | 16以上、または「監査なし」「1つの鍵で何でもできる」のどちらか | 練習だけ（小資金のときは入れてよいが警告） |

画面には、推奨金額と理由を一緒に出します（例:「上限 $500。会場が動いて60日、監査1件で直っていない問題あり」）。上限を超えたいときは、確認を1回はさみます。点数のもとにした情報は、出典と確認日を会場の設定ファイルに書きます。自動で読めないもの（監査の中身など）は実装役が調べて書き、分からないものは「不明」として3点として数えます。

### 5.4 全体で損したときの線

- 3段階（注意＝知らせるだけ、新しく入らない、すべて止める）× 数える期間（1日、1週間、始めてから）。それぞれ % と金額のどちらでも決められ、画面には両方を出します。
- 損の数え方: まだ売っていないボーナスのコインは今売った値段、保険の損益も合わせる、移る費用とガス代も入れる。
- 最初の数字は、練習と過去のデータの「1日の損益の揺れ」からアプリが提案します。案: 注意＝100日に5日くらいの大きさの損、新しく入らない＝100日に1日くらい、すべて止める＝その1.5倍。
- 提案が出るまでは、今の決まり（1日に総資産の−5%ですべて止める）だけを使います。

### 5.5 止め方

段階ごとに「自動で出る / 知らせて決める / 知らせて、返事がなければ一定時間後に出る」を選べます。

| 場面 | 段階1 | 段階2〜4 | 全体の損の線 |
| --- | --- | --- | --- |
| 練習（今） | 自動 | 自動（記録をそろえるため） | 自動 |
| 本物のお金（Phase 3。案） | 自動（変えるときは確認を1回） | 知らせて、30分返事がなければ出る | 自動 |

### 5.6 練習の上限と本番の上限を分ける

設定の上限を「練習用」と「本番用」の2つに分けます。本番用は Phase 3 まで使いません。今の上限（1建玉 $1,000、合計 $3,000、1会場 50%、1日20件）をどう振り分けるかは、オーナーが決めます（11章）。

## 6. 試す

試す仕組みは、練習と同じ「計算」と「決まりの表」に、過去のデータを流し込む形にします。練習と試すで別の計算を作らないので、試した結果がそのまま練習の決まりになります。

### 6.1 過去のデータで計算し直す

- 「もし最初から入っていたら」を、時間の順に再現します。入る・出る・移るは「決まりの表」どおりにします。
- 使うデータ: 自分の15分ごとの記録（up. と Alandale、9/27 から）、DefiLlama の過去の利回りと預かり額（1日ごと）、Merkl の終わったキャンペーン、コインの過去の値段、必要なプールだけチェーンの過去の記録。
- 比べる相手: 同じ期間に「何もしない（ドルのまま）」と「レンディングに置く」。
- 最初の題材: up. の立ち上げ直後に入り、決まりどおり出ていたら。自分の記録がない期間は、チェーンの過去の記録から作り直します。

### 6.2 いろいろな場面

実際の過去に、作った「事件」を差し込んで試します。各場面で、決まりがどう動いて、いくら残ったかを並べます。

| 場面 | 中身 | 確かめること |
| --- | --- | --- |
| 利益が出る | ボーナスが安定して続く | 入って、終わり前に出て、次へ移れるか |
| 利益が出ない | 人が一気に集まって薄まる | 段階2で早めに出て、移る費用で損しすぎないか |
| 損が出る | ボーナスのコインが1日で−50% | 売り方（毎日売る）で損がどこまで抑えられるか |
| 損が出る | 預かり額が1時間で半分に（ハッキング） | 段階1の遅れでどれだけ失うか |
| 損が出る | ドルのコインが3%ずれる、ガス代が20倍、送金サービスが止まる | 出口がふさがったときにどうなるか |
| 損が出る | キャンペーンが予告なしに終わる | 段階3を待たずに動けるか |

### 6.3 練習の自動記録（前に頼まれた①）

- 建玉を持った瞬間から、ボタンなしで自動で記録します。
- あとから好きな期間を切り出して、今の評価と同じ基準で判定できます（今の評価の計算を使い回す）。
- 今の評価（10/15 まで）の答え合わせも、この切り出しで行います。

### 6.4 試した結果の扱い

試した結果は、本物より良く出やすいものとして見ます。1日ごとのデータでは1日の中の値動きが消えること、潰れた会場はデータから消えやすいことが理由です。画面には「データの細かさ」を必ず書きます。

## 7. 記録と税金、日本からの入金、画面

取引は1回ずつ、税金の計算に要る項目をそろえて記録し、税金ツールにそのまま取り込める形で書き出します。今の台帳には足りない項目が多いので、作り直します。

### 7.1 記録する項目

- いつ（世界時間で保存し、日本時間で書き出す）、チェーン・会場・取引の番号
- 種類（交換・預け入れ・引き出し・ボーナスの受け取り・送金・ガス代・保険）
- 出したコインと受け取ったコイン（名前・住所・量）、手数料
- ドルの値段とその出どころ、円のレートとその出どころ・日付、円での価値
- 練習か本物か、預け入れと引き出しを結ぶ番号、ボーナスが生まれた時と受け取った時

### 7.2 書き出しの形

- Gtax の「共通フォーマット」（日本時間、1回の交換を1行）と、クリプタクトの「カスタムファイル」（1回の交換を「売り」と「買い」の2行）のどちらも作れます。使うツールを1つ決めてください（11章）。
- 練習の取引は、本物の書き出しには入れません。練習の書き出しは「形の確認用」として別に出します。
- LP は、預け入れと引き出しの差（損益）だけを書き出します。どちらのツールもこの扱いが標準です。細かい記録はアプリの中に全部残します。

### 7.3 税金ではっきりしないこと（税金ツールか専門家で確かめる）

- LP への預け入れが「売った」ことになるか（国の決まりはない）
- ボーナスを「いつ」の収入にするか、ガス代を経費にできるか、送金（ブリッジ）の扱い
- USDC と USDG の扱い（日本の法律では USDC は「支払いの手段」で、暗号資産とは別）
- 円のレート: 今は欧州中央銀行の値。決まりは主な取引銀行の仲値（TTM）なので、書き出しでは TTM も選べるようにします
- 国内の交換業者を通さない DeFi の取引は、20% の分離課税の対象外で、ほかの所得と合わせて最大55%です（分離課税が始まる日は未定）

### 7.4 日本からの入金の経路

| 経路 | 上限 | 費用の目安 | 注意 |
| --- | --- | --- | --- |
| SBI VCトレードの USDC | 1回の注文と1回の出金がそれぞれ100万円まで | 前の調べを参照 | SBI の中の残高が100万円を超えると、超えた分を買い戻されることがある。分けて送って上限を避けると、決まりを避ける行為と見られるおそれ |
| 国内の取引所で ETH を買って送る（例: GMO コイン） | 送金は1日2億円まで | 合計 約0.05〜0.15%（売買 0.05%、チェーンの上の交換 0〜0.09%、送金は無料） | 新しい送り先は24時間待つ。買ってから送るまで ETH の値動きを受ける |
| JPYC | 1回の発行が100万円まで | USDC に替えるのに 約1.3〜1.7% | 費用が高め |

資金が100万円を超えるようになったら、「ETH を買って送る」経路がいちばん安くなります。経路は「学ぶ」に載せ、入金の操作そのものはアプリでは作りません。

### 7.5 画面

- ページは「ホーム・機会・渡る・守る・試す・学ぶ」にします。見た目は今の案B（スマホ向けの暗い画面）のままです。
- ホーム: どこにいくら置いているか、損の線までの距離、今日の動き、新しい合図。
- 機会: 本当に残る利回りの順。金額ごとの利回り、取り返す日数、危なさ、推奨金額と理由。
- これまで頼まれた表示の直し（「$1,000 を試す」の位置、古いお知らせ、会場ごとのプール一覧、監査の欄）は、新しいページを作るときに入れます。

## 9. 今のコードで残すもの・作り直すもの

計算と読み取りの土台はほとんど残せます。作り直すのは「何を見るか」と「どう決めるか」の部分と、画面です。今の記録（データベース）はそのまま引き継ぎ、列や表を足すだけにします。

| 部分 | 扱い | 理由 |
| --- | --- | --- |
| チェーンの読み取り（再試行・切り替え・まとめ読み・取りすぎの制御） | 残す | ETH系ならどのチェーンでも同じ |
| up. と Alandale の読み方 | 残して「型」に入れ直す | 幅に配る型・投票型の最初の例になる |
| 値動きの目減り・置き直し・値崩れ・保険の計算 | 残す | 評価で答え合わせしている部分。チェーンを知らない形に切り出す |
| 値動きの大きさ（ボラ）、値段、円のレート、米国市場の休日 | 残す | そのまま使える |
| Lighter（保険）の読み取り | 残す | そのまま使える |
| 会場のプログラムの変化の見張り | 残して広げる | 段階1の合図になる。「予約された変更」も読む |
| 練習の建玉と、損益の6区分 | 残して広げる | 複数のチェーン・会場、移る費用、ボーナスの売却を足す |
| 評価の計算（週ごとの見込みを含む） | 残して使い回す | 「あとから期間を切り出す」判定の中身になる |
| 通知と毎朝のレポート、Telegram | 残す | 合図の知らせに使う |

## 10. 難しいところ・無理なところ・危ないところ

いちばん大きいのは、「練習ではうまく逃げられても、本物のお金では逃げられないことがある」点です。そのほかは、工夫すれば作れますが、数字が控えめになることを前提にしてください。

### 無理なところ（今の決まりの中では作れない）

- 本物のお金で自動で出る・移るには、署名と送信が要ります。これは Phase 3 で、「Phase 3aを開始」までは作りません。この設計で作るのは、見つける・計算する・練習で渡る・試す・記録する、までです。
- ポイントの利回りは計算できません。将来の値段が決まっていないためです。量だけ表示し、利回りは0として扱う案にしました（11章）。

### 難しいところ

- 人が集まって薄まる分の見込み。新しいキャンペーンは、始まってすぐに預かり額が何倍にもなり、利回りが大きく下がることがよくあります。最初は控えめな仮置きで、過去のデータで直していきます。
- 過去のデータの粗さ。多くは1日ごとで、1日の中の値動きや逃げるタイミングは再現できません。新しい会場はまだ外のデータに載っていないことも多いです。
- 会場ごとの確認の手間。「住所の登録だけで読める」ように型を作りますが、住所の出典と、配り方の仕組みの確認は、絶対ルールどおり毎回必要です。アプリが候補を出し、実装役が確かめて登録する形になります。
- 読み取りの量。チェーンと会場が増えると、無料の読み取り口では「取りすぎ」で断られます。持っている場所だけ細かく見て、候補は粗く見るように分けます。それでも、いずれ Alchemy などのキーが要ります。
- ボーナスのコインの売り場。新しいコインは売り場が浅く、$100,000 の規模では「利回りは高いのに売れない」が起きます。
- 参加できる人の制限。Merkl には「特定の利用者だけ」のキャンペーンがあります。日本から参加できるかは、一つずつ確かめる必要があります。
- 税金。LP への預け入れ・引き出しの扱いは、国の説明にはっきりした決まりがない部分があります（7章）。アプリは全部を記録して書き出しますが、最後の判断は税金のツールか専門家になります。

### 危ないところ

- ハッキングのとき、本物のお金では逃げられないことがあります。会場が一時停止したり、みんなが一度に逃げてガス代が跳ね上がったり、送金サービスが止まったりするためです。15分ごとの見張りでは、気づいたときには終わっていることもあります。守りの中心は「危ない場所に多く置かない」こと（5章の上限）で、逃げる仕組みは補助と考えてください。
- 新しいチェーンは、出口が公式の送金だけで、引き出しに何日もかかることがあります。入る前に「出口の経路とかかる時間」を必ず調べ、少ない金額で入れて出す試しを先にします（2章）。
- 自動で動く仕組みそのものが狙われます。Phase 3 では、許された操作だけできる財布（付録A）を使い、複数のチェーンにそれぞれ上限をかける必要があります。
- パソコンでの常時運転。チェーンが増えて「すぐ逃げる」を本物で使うときは、止まらない場所（VPS）が必要になります。
- 「誰でも作れるキャンペーン」の罠。利回りが異常に高いものは、ボーナスのコインに価値がない、すぐ終わる、対象が一部の人だけ、などのことが多いです。売り場の確認と「利回りが高すぎる」警告で外します。
- 早く抜けると報酬を失う仕組み。Aerodrome の幅に配るプールは、決められた時間（今は10秒〜5分）より前に抜けると、受け取る前の報酬が全部なくなります。運営はこの時間を最大で1週間まで延ばせるので、段階1で逃げるときに報酬を失うことがあります。会場ごとにこの時間を読み、「出るときに失う分」を費用に入れます。
- 報酬の取り上げ。Pharaoh は中身が非公開の「不正の判定」で報酬を取り上げられます。Merkl も、置き直しが多すぎると「水増し」として外されることがあります。「入って早めに出る」使い方が対象になるかは分からないので、この会場は危なさの点数を上げます。
- 10/22 の Aero への切り替え。Base、Arc、Robinhood Chain で仕組みが変わります。古いボーナスがいつ止まるか、新しい住所、読み方はまだ公開されていません。公開されて確かめられるまで、Aero は Merkl と DefiLlama の数字だけで見ます（2.5 の段階A）。
